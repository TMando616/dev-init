# Phase 15: 学生アカウント機能の整備

## 概要

**目的**: 受講生が自分のアカウント情報を自分で管理できるようにする。プロフィール編集・パスワード変更・パスワードリセット・退会・復会の5導線を追加し、「登録したら二度と変更できない」状態を解消する。

**対象ユーザー**: 受講生（学生）。管理者は、退会（ソフトデリート）導入に伴う一覧・削除挙動の変更のみ影響を受ける。

**背景・課題**:
- 受講生向けの認証機能は登録・ログイン・ログアウトのみ（`backend/app/Http/Controllers/AuthController.php`）。名前・メールアドレスの変更手段がなく、誤登録した場合は管理者に依頼するしかない。
- パスワードを変更する手段がない。漏洩を疑ったときに受講生自身が対処できない。
- パスワードを忘れた場合の復旧導線がない。`password_reset_tokens` テーブルはLaravel標準マイグレーション（`0001_01_01_000000_create_users_table.php`）で作成済みだが、使うルート・通知が一切実装されていない。
- 退会（アカウント削除）の導線がない。個人情報保護法上の削除請求に、受講生自身の操作で応じる手段がない状態（詳細は末尾「個人情報の取り扱いに関する注記」）。
- メール送信基盤が未整備。`backend/.env.example` は `MAIL_MAILER=log`、`docker-compose.yml` にメール関連サービスなし。パスワードリセットを実装するには開発環境で受信確認できる仕組みが要る。

**今回の方針決定（確定事項）**:
- パスワードリセットは**本フェーズに含める**。開発環境のメール受信確認には **Mailpit** を `docker-compose.yml` に追加する。本番SMTPの選定・設定は本フェーズの対象外（環境変数で差し替え可能な形にするところまで）。
- 退会は**ソフトデリート**を採用する（`deleted_at`）。退会時点での物理削除は行わない。
- 退会済みアカウントは**復会（アカウント復元）できる**ものとする。復会すると過去の提出データ（`submissions`）と学習進捗をそのまま引き継ぐ。
- 復会の本人確認は**メール到達確認**で行う。退会済みメールアドレスで新規登録しようとした場合、その場でアカウントを作らず復会リンクをメール送信し、リンクから新しいパスワードを設定して復会させる。理由: 登録フォームだけで復会できると、メールアドレスを知っている別人が退会者の氏名・提出コードごとアカウントを引き継げてしまうため。
- 退会データの保持期間は**30日**とする。30日を過ぎた退会済みアカウントはスケジューラーで自動的に完全削除する（復会不可になる）。
- リセットリンクの遷移先はNext.js側の画面とする。Laravel標準の `ResetPassword` 通知はバックエンドURLを指すため、フロントエンドURLを向くようカスタマイズする。
- メールアドレス変更時の確認メール（メール到達性の検証）は**対象外**とする。`email_verified_at` は既存カラムとして残すが本フェーズでは利用しない。
- 管理者による受講生アカウント作成・編集・削除（`/api/admin/users`）の画面仕様は変更しない。ただしソフトデリート導入に伴う挙動変更はUS-7で吸収する。

## ユーザーストーリー

### US-1: プロフィール（名前・メールアドレス）の編集

**As a** 受講生
**I want** 自分の名前とメールアドレスを設定画面から変更したい
**So that** 誤って登録した情報や、変わった連絡先を自分で直せる

#### 受け入れ条件

- [x] 受講生としてログインした状態で、サイドバーから設定画面（`/settings`）へ遷移できる
- [x] 設定画面に現在の名前・メールアドレスが初期値として表示される
- [x] 名前を変更して保存すると、レスポンスと画面表示（サイドバーのユーザー名を含む）に即座に反映される
- [x] メールアドレスを変更して保存すると、変更後のメールアドレスでログインできる
- [x] メールアドレスを変更する場合は**現在のパスワードの入力が必要**で、誤っていると422が返る（名前だけの変更には不要）
- [x] 他の受講生が既に使っているメールアドレスに変更しようとすると422が返り、画面にエラーメッセージが表示される
- [x] 自分自身の現在のメールアドレスのまま保存した場合は、重複エラーにならず正常に保存できる
- [x] 未ログインで更新APIを叩くと401が返る
- [x] バリデーションはFormRequestに定義する（Controller内での `validate()` 直書きをしない。Phase 14の方針を踏襲）

---

### US-2: パスワード変更

**As a** 受講生
**I want** ログイン中に自分のパスワードを変更したい
**So that** 漏洩が疑われるときに自分で対処できる

#### 受け入れ条件

- [x] 設定画面に「現在のパスワード」「新しいパスワード」「新しいパスワード（確認）」の入力欄がある
- [x] 現在のパスワードが誤っている場合は422が返り、パスワードは変更されない
- [x] 新しいパスワードは8文字以上・確認入力との一致（`confirmed`）を満たさない場合422になる
- [x] 変更に成功すると、新しいパスワードでログインでき、古いパスワードではログインできない
- [x] 変更に成功すると、**操作中の端末以外のアクセストークンは全て失効する**（別端末は再ログインが必要になる）
- [x] 変更後も操作中の端末はログアウトされず、そのまま操作を続けられる
- [x] パスワード変更エンドポイントは `throttle:auth` 相当の厳しめのレート制限下にある

---

### US-3: パスワードリセット（メール経由）

**As a** パスワードを忘れた受講生
**I want** メールで届いたリンクからパスワードを再設定したい
**So that** ログインできなくなっても自力で復旧できる

#### 受け入れ条件

- [x] ログイン画面（`/login`）に「パスワードをお忘れの方」リンクがあり、`/forgot-password` へ遷移できる
- [x] `/forgot-password` でメールアドレスを送信すると、登録済み・未登録にかかわらず**同一の成功メッセージ**が表示される（アカウントの存在有無を推測されないため）
- [x] 登録済みのメールアドレスの場合、リセットリンクを含むメールが送信される
- [x] 開発環境では Mailpit（`http://localhost:8025` 等）でそのメールを確認できる
- [x] メール内のリンクはフロントエンドの `/reset-password?token=...&email=...` を指しており、クリックすると再設定フォームが開く
- [x] 新しいパスワードを送信すると変更が完了し、そのパスワードでログインできる
- [x] 一度使用したトークンは再利用できない（2回目は422）
- [x] 有効期限切れ・改ざんされたトークンでは再設定できず、エラーメッセージが表示される
- [x] 退会済み（ソフトデリート済み）のメールアドレスにはリセットメールが送信されない
- [x] `/forgot-password`・`/reset-password` の両APIは `throttle:auth` 相当のレート制限下にある

---

### US-4: 退会（アカウント削除）

**As a** 受講生
**I want** 自分のアカウントを削除したい
**So that** サービスの利用をやめるときに自分のデータを残さずに済む

#### 受け入れ条件

- [x] 設定画面に退会セクションがあり、**現在のパスワード入力**と確認ダイアログを経ないと実行できない
- [x] 退会を実行すると `users.deleted_at` がセットされ、保持している全アクセストークンが失効する
- [x] 退会後、同じメールアドレス・パスワードではログインできない（401または422）
- [x] 退会前に発行済みのトークンでAPIを叩いても401になる
- [x] 退会が完了するとフロントエンドはログアウト状態になり、ログイン画面へ遷移する
- [x] 退会済みユーザーの `submissions` レコードは削除されない（`deleted_at` の付与のみ。復会時に学習進捗を引き継ぐため）
- [x] 退会画面に「30日以内であれば同じメールアドレスで復会できる／30日を過ぎるとデータは完全に削除される」旨が明記されている

---

### US-5: 復会（退会済みアカウントの復元）

**As a** 一度退会した受講生
**I want** 同じメールアドレスで戻ってきて、以前の学習進捗を引き継ぎたい
**So that** やり直しではなく続きから学習を再開できる

#### 受け入れ条件

- [x] 退会済みのメールアドレスで新規登録しようとすると、**その場ではアカウントが作られない**（新規ユーザーレコードは増えない）
- [x] 上記の場合、復会リンクを含むメールが送信され、画面には「入力されたメールアドレス宛に確認メールを送った」旨の案内メッセージが表示される
- [x] 有効なアカウントが存在するメールアドレスでの新規登録は、従来どおり422（メールアドレス重複エラー）を返す
  - 補足: 当初は「登録済み・退会済みを問わず同一メッセージ」とし、退会済みかどうかを外部から判別できないようにする案だったが、レスポンスの出し分けをやめると全ユーザーが「メールアドレスは既に使用されています」というエラーを受け取れなくなり、登録できない理由がメールを開くまで分からなくなる。DevInitにおいて「特定の人が退会した」ことが漏れる実害は小さいと判断し、**退会済みアカウントの存在は推測されうるが許容する**方針を採る（2026-08-06 決定）
- [x] 復会リンクは `/reactivate?token=...&email=...` を指し、開くと新しいパスワードの設定フォームが表示される
- [x] パスワードを設定して送信すると `deleted_at` がクリアされ、そのメールアドレス・新パスワードでログインできる
- [x] 復会後、退会前の `submissions`（保存コード・完了状態）とダッシュボードの進捗が退会前と同じ内容で表示される
- [x] 復会に使ったトークンは再利用できない
- [x] 退会から30日を超えたアカウントは復会できない（該当メールでの登録は通常の新規登録として扱われる。ただし自動削除バッチ実行後はレコード自体が存在しない）
- [x] 有効な（退会していない）メールアドレスでの新規登録は、従来どおり即座にアカウントが作られる（既存の登録フローを壊さない）
- [x] 復会エンドポイントは `throttle:auth` 相当のレート制限下にある

---

### US-6: 保持期間を過ぎた退会アカウントの自動削除

**As a** サービス運営者
**I want** 退会から30日を過ぎたアカウントを自動的に完全削除したい
**So that** 不要になった個人情報を無期限に保持せずに済む

#### 受け入れ条件

- [x] 退会から30日を超えたユーザーを完全削除するArtisanコマンドがある
- [x] コマンド実行後、対象ユーザーの `users` レコードと関連 `submissions` が削除される（`submissions` は `cascadeOnDelete` 済み）
- [x] 退会から30日以内のユーザー、および退会していないユーザーは削除されない
- [x] コマンドは1日1回スケジュール実行される（`routes/console.php` に登録）
- [x] 削除件数がログに記録される
- [x] 開発環境でスケジューラーを動かす手段が用意されている（`schedule:work` を回すサービス構成などは設計で決定）
- [x] `--dry-run` 相当の手段で、実削除せず対象件数を確認できる（誤削除の事故を防ぐため）

---

### US-7: 管理者側の退会済みユーザーの扱い

**As a** 管理者
**I want** 退会済みの受講生を一覧から区別し、必要なら完全に削除したい
**So that** 通常の運用画面を汚さず、削除請求には確実に応じられる

#### 受け入れ条件

- [x] `/admin/users` の一覧に退会済みユーザーは表示されない（デフォルト）
- [x] 管理画面から退会済みユーザーを表示する手段がある（フィルタ・タブなど手段は設計で決定）
- [x] 管理者が受講生を削除する既存操作（`DELETE /api/admin/users/{id}`）はソフトデリートになる
- [x] 退会済みユーザーに対して**完全削除（物理削除）**を実行でき、実行すると `users` レコードと関連 `submissions` が削除される（`submissions` は `cascadeOnDelete` 済み）
- [x] 完全削除は確認を挟んだ上で実行される（誤操作防止）
- [x] 退会済みユーザーは受講生数などの集計対象から除外される

## 個人情報の取り扱いに関する注記

本フェーズは個人情報（メールアドレス・氏名）の変更と削除を扱うため、以下の未整備項目を明示しておく。**本フェーズで実装するかは別途判断**とし、対応しない場合も「未整備であること」を記録として残す。

| 項目 | 現状 | 備考 |
|------|------|------|
| プライバシーポリシー | ページなし | 収集する情報（氏名・メール・提出コード）・利用目的・第三者提供の有無を明記したページが必要 |
| 同意取得 | 登録フォームに同意チェックなし | プライバシーポリシー整備後に登録画面へ追加するのが自然 |
| 削除請求への対応 | 本フェーズのUS-4・US-6・US-7で対応 | 退会（US-4）はソフトデリートのため個人データが30日間残る。30日経過後は自動削除（US-6）、即時削除の請求には管理者の完全削除（US-7）で応じる |
| 開示・訂正請求 | 訂正はUS-1で自己対応可能に | 開示（自分のデータのエクスポート）は未対応 |
| 保持期間 | US-6で「退会後30日で完全削除」を実装 | 保持期間を定めたことになるため、プライバシーポリシー作成時にこの期間を明記する |
| 収集の最小化 | 氏名・メール・パスワードのみで過剰な収集はなし | 問題なし |
| オプトアウト | 通知メール配信なし（リセットメールは本人操作起点のトランザクションメール） | 現状は不要 |

## 対象外（Out of Scope）

- メールアドレス変更時の到達確認メール（`email_verified_at` の運用）
- 新規登録時のメール認証
- 本番環境のSMTPプロバイダ選定・設定
- 管理者自身（`admins` テーブル）のプロフィール編集・パスワードリセット
- プライバシーポリシーページの作成、登録時の同意取得UI
- 自分のデータのエクスポート機能
